# Фото в Telegram

Мини-приложение для Telegram: фотогалерея в стиле «Фото» на iPhone, где **хранилище — сам Telegram**.
Каждый пользователь хранит фото в своём личном чате с ботом, а приложение показывает их так же, как галерея
Яндекс Диска: «Медиатека» (Годы / Месяцы / Все фото, щипок, ползунок прокрутки), «Коллекции» (недавние дни,
«В этот день», поездки, люди, избранное, альбомы) и «Поиск» (по дате, подписи, имени и умный поиск по
содержимому — анализ идёт на самом телефоне).

Всё работает на бесплатных тарифах, без своего сервера (VPS):

- **сайт с галереей** — GitHub Pages;
- **маленький сервер** — Cloudflare Workers + база D1. Он хранит токен бота (в браузер токен не попадает),
  запоминает, какие фото пришли боту, и отдаёт каждому пользователю только его фото.

**Инструкция для пользователей бота** — [docs/user-guide.md](docs/user-guide.md).

## Как это устроено

```
 iPhone / Android                      Cloudflare (бесплатно)                Telegram
┌──────────────────────┐   initData   ┌───────────────────────────┐  Bot API  ┌──────────────────┐
│ Мини-приложение      │ ───────────▶ │ Worker:                   │ ────────▶ │ ваш чат с ботом  │
│ (GitHub Pages)       │ ◀─────────── │  /api/list, /api/file,    │ ◀──────── │ (фото хранятся   │
│                      │   фото       │  /api/upload              │  вебхук   │  здесь)          │
└──────────────────────┘              │ D1: список фото (file_id) │           └──────────────────┘
 «Быстрые команды» ──── ключ ───────▶ │  /api/upload, /api/auto/* │
                                      └───────────────────────────┘
```

- Фото, которые вы **присылаете боту руками**, приходят на сервер через вебхук и записываются в базу.
  Без сжатия — отправляйте файлом.
- Кнопка **«+»** в галерее отправляет фото с телефона в ваш чат с ботом альбомами по 10 —
  в обычном качестве или оригиналами.
- **Автозагрузка с iPhone** — готовой «Быстрой командой»: в галерее «Подключить автозагрузку» →
  «Добавить команду» → вставить ключ. Настройки (оригиналы, старые фото) — в галерее: [инструкция](docs/shortcut.md).
- **Старые фото за несколько лет** — той же командой, переключателем «Загрузить и старые фото».
- Каждый запрос из приложения подписан Telegram (`initData`). Сервер проверяет подпись токеном бота и берёт
  номер пользователя только оттуда, поэтому чужие фото не получить, даже подделав запрос.

## Попробовать без Telegram

Нужен Node.js 20 или новее.

```bash
npm install
```

```bash
npm run dev
```

Откройте http://localhost:5173/?mock — демо-галерея со снимками с picsum.photos. «Загрузка» в демо
ничего никуда не отправляет. Демо есть только при `npm run dev`, в рабочую сборку оно не попадает.

## Установка

Понадобится: Mac с Node.js 20+, аккаунт GitHub, Telegram и бесплатный аккаунт Cloudflare.
Все команды выполняются в папке проекта.

### 1. Бот

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя и адрес бота.
2. BotFather пришлёт **токен** вида `123456789:AA...`. Это ключ от бота: никому его не показывайте
   и не вставляйте в код или на сайт. Он понадобится в шагах 3 и 6.

### 2. Cloudflare и база

```bash
npx wrangler login
```

Откроется браузер — войдите в Cloudflare (или зарегистрируйтесь, бесплатно) и разрешите доступ.

```bash
npx wrangler d1 create tg-photos
```

Команда выведет `database_id`. Вставьте его в [wrangler.toml](wrangler.toml) вместо нулей. Затем создайте
таблицы:

```bash
npm run db:init
```

### 3. Секреты сервера

Токен бота сохранит на сервере скрипт из шага 6 — отдельно вводить его не нужно.

Секрет для вебхука — по нему сервер отличает настоящие сообщения от Telegram от поддельных.
Сгенерируйте случайную строку, сохраните её в файл `.webhook-secret` (понадобится в шаге 6) и передайте серверу:

```bash
openssl rand -hex 32 | tr -d '\n' > .webhook-secret
```

```bash
npx wrangler secret put WEBHOOK_SECRET < .webhook-secret
```

### 4. Настройки и запуск сервера

Проверьте раздел `[vars]` в [wrangler.toml](wrangler.toml):

- `ALLOWED_ORIGIN` — адрес сайта с галереей без пути: `https://wickedslim.github.io`;
- `WEBAPP_URL` — полный адрес галереи: `https://wickedslim.github.io/tg-photo-bot/`;
- `ALLOWED_USERS` — пусто, если ботом может пользоваться кто угодно. Чтобы бот был только для своих,
  перечислите номера пользователей Telegram через запятую (свой номер покажет, например, @userinfobot).

```bash
npm run worker:deploy
```

В конце будет адрес сервера вида `https://tg-photo-bot.<ваше-имя>.workers.dev`. Откройте его в браузере —
должно быть написано `tg-photo-bot: ok`.

### 5. Сайт на GitHub Pages

1. Создайте на GitHub репозиторий `tg-photo-bot` и отправьте туда этот проект.
2. **Settings → Pages → Source: GitHub Actions.**
3. **Settings → Secrets and variables → Actions → Variables → New repository variable:**
   имя `API_URL`, значение — адрес сервера из шага 4.
4. Каждый push в `main` собирает и публикует сайт ([deploy.yml](.github/workflows/deploy.yml)).
   Галерея будет по адресу `https://wickedslim.github.io/tg-photo-bot/`.

### 6. Связать бота с сервером

Запишите адрес сервера в файл `.worker-url` (или скрипт спросит его сам) и запустите:

```bash
npm run setup-bot
```

Скрипт спросит токен бота — ввод не виден на экране и не остаётся в истории команд. Он проверит токен в Telegram и сохранит его в секретах сервера (`BOT_TOKEN`). Секрет вебхука он
возьмёт из файла `.webhook-secret`, если вы сохранили секрет туда (оба файла в git не попадают), иначе
передайте его переменной `WEBHOOK_SECRET`. Скрипт вызывает `setWebhook` с секретом, добавляет в чат с ботом
кнопку «Галерея» и команду /start. Напишите боту `/start` — он ответит кнопкой «Открыть галерею».

## Ограничения

**Telegram**
- Фото, отправленное как фото (`sendPhoto`), Telegram сжимает: самая большая сторона — до **2560 px**.
  Поэтому «обычное качество» в галерее — это 2560 px. Файл для `sendPhoto` — до 10 МБ (приложение
  само уменьшает фото перед отправкой).
- Оригинал (документом) — до **50 МБ** на файл.
- Сервер может скачать из Telegram файл **до 20 МБ** (`getFile`). Оригиналы больше 20 МБ в галерее видны
  только маленькой обложкой, целиком их можно открыть в чате с ботом.
- Писать в один чат Telegram разрешает примерно раз в секунду. Альбом из 10 фото — это 10 сообщений, поэтому
  большая загрузка идёт неспешно: 1000 фото — порядка 20–30 минут. Если Telegram просит подождать,
  приложение ждёт и продолжает само.
- **Дата и место съёмки.** У фото, отправленного боту обычной фотографией, Telegram стирает дату съёмки
  и геометку — в галерее у такого фото будет дата отправки. Чтобы сохранить дату и место, присылайте фото
  **файлом** (📎 → Файл) или загружайте кнопкой «+» в галерее и автозагрузкой: тогда дата и место берутся
  из самого снимка. По месту съёмки собираются разделы «Поездки» и «Места».
- Удалить фото можно корзиной в галерее: оно пропадёт из галереи и из чата. Сообщения старше 48 часов Telegram
  не даёт боту удалять: если фото загружено через галерею, автозагрузку или «Архив», бот заменит его в чате
  заглушкой «Фото удалено»; если вы прислали его боту сами — удалите сообщение в чате вручную. А если удалить сообщение прямо в чате, бот этого
  не узнает, и фото останется в галерее.
- Видео пока не поддерживаются.

**Cloudflare, бесплатный тариф**
- Workers: **100 000 запросов в сутки**. Каждая миниатюра — один запрос. Первый просмотр галереи из 1000 фото
  стоит 1–2 тысячи запросов, дальше миниатюры берутся из памяти телефона.
- Запрос к серверу — до 100 МБ (приложение отправляет пачки до 40 МБ).
- D1: 5 ГБ, 5 млн чтений и 100 000 записей в сутки. Одна запись в базе — это одно фото, примерно полкилобайта,
  так что места хватит на миллионы фото.

**Автозагрузка с iPhone** — по расписанию и после съёмки, не мгновенно, до 100 фото за запуск.
Подробно — в [инструкции](docs/shortcut.md#насколько-это-надёжно).

## Приватность — честно

- Ваши фото лежат в вашем личном чате с ботом. **Другие пользователи бота их не видят**: сервер отдаёт фото
  только тому, кому оно принадлежит, и проверяет это по подписи Telegram.
- Но **владелец бота технически может получить доступ к фото всех пользователей**: у него есть токен бота,
  а через него — доступ к файлам в чатах с ботом, и у него есть база со списком фото. Если ботом
  пользуются другие люди, они должны это понимать.
- Telegram хранит фото на своих серверах так же, как любые сообщения в обычных (не секретных) чатах.
- Возможное улучшение на будущее — шифрование фото на телефоне до отправки. Тогда ни бот, ни Telegram
  не смогут их посмотреть.

## Для разработчика

```
src/              мини-приложение (Vite, без фреймворков; сетка, просмотр, загрузка)
worker/src/       сервер на Cloudflare Workers
  auth.js         проверка initData, токены для файлов
  telegram.js     Bot API: вызовы, getFile, разбор сообщений с фото
  db.js           запросы к D1 (всегда с условием user_id)
  index.js        адреса API и вебхук
worker/migrations схема базы
scripts/          setup-bot.mjs (настройка бота), dev-initdata.mjs (initData для проверок)
test/             тесты: подпись initData, доступ только к своим фото, ключи автозагрузки
docs/shortcut.md  инструкция по «Быстрым командам»
docs/archive.md   прежний способ для старых фото (отдельная команда «Архив»)
docs/channel.md   фото в приватном канале (удаление любой давности)
```

Тесты — проверка подписи и полноценный сервер в Miniflare (локальный Cloudflare) с настоящей D1
и подставным Telegram:

```bash
npm test
```

Сервер локально (тестовый токен — в `.dev.vars`, образец — `.dev.vars.example`):

```bash
cp .dev.vars.example .dev.vars
```

```bash
npm run db:init:local
```

```bash
npm run worker:dev
```

Запрос «как будто из Telegram»:

```bash
curl -H "Authorization: tma $(node scripts/dev-initdata.mjs)" http://localhost:8787/api/list
```

Для галереи против локального сервера: `VITE_API_URL=http://localhost:8787 npm run dev`. Правда, вне Telegram
приложение покажет заглушку, так что для интерфейса удобнее `?mock`.

**Безопасность страницы.** Как и у галереи Яндекс Диска, в собранную страницу встраивается строгая политика CSP:
скрипты — только свои и telegram.org, запросы — только к своему серверу, картинки — только свои и `blob:`.

**Wrangler** закреплён на версии 4.86 — последней, которая работает на Node.js 20. С Node.js 22+ можно обновить.
